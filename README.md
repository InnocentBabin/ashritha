## ✨ Features

### 🔍 Reconnaissance
- Automated web crawling with depth control
- JavaScript file analysis for secrets and API keys
- Form and input field discovery
- API endpoint detection
- Optional authentication support

### 🧠 AI-Powered Vulnerability Analysis
- Uses **Ollama** (local LLM) for intelligent analysis
- Context-aware vulnerability detection
- Risk scoring with confidence levels
- No data sent to external servers — 100% local

### 🔨 Automated Exploitation
- SQL Injection (UNION, error-based, time-based)
- Cross-Site Scripting (XSS)
- Command Injection
- Path Traversal
- IDOR (Insecure Direct Object References)
- **Custom payloads** generated by AI

### 🔧 Technology Fingerprinting
- **Wappalyzer** integration
- **WhatWeb** integration
- CVE matching for detected technologies
- Exploit command suggestions

### 📊 Comprehensive Reporting
- JSON and text reports
- Curl commands for manual verification
- Proof of concepts
- Working payloads list

## 🛠️ Installation

### Step 1: Install Ollama (Required)

Ollama is required for AI-powered vulnerability analysis and custom payload generation.

#### 🐧 Linux

```bash
curl -fsSL https://ollama.com/install.sh | sh
```

#### 🍎 macOS

```bash
# Download from https://ollama.com/download/mac
# Or use Homebrew
brew install ollama
```

#### 🪟 Windows

Download the installer from:
👉 https://ollama.com/download/windows

#### ✅ Verify Ollama is Running

```bash
ollama --version

# Start the Ollama service
ollama serve
```

**Note:** Keep `ollama serve` running in a separate terminal, or set it as a background service.

---

### Step 2: Pull an AI Model (Required)

Choose a model based on your hardware:

#### 🟢 Lightweight (4 GB RAM — Works on most machines)

```bash
ollama pull llama3.2:3b
```
- ⚡ Fast
- 💾 Small (~2 GB)
- ✅ Good for basic analysis

#### 🟡 Balanced (8 GB RAM — Recommended)

```bash
ollama pull llama3.1:8b
```
- ⚡ Fast
- 💾 Medium (~5 GB)
- ✅ Great for vulnerability analysis

#### 🔴 Powerful (16 GB RAM — Best quality)

```bash
ollama pull llama3.1:70b
# or
ollama pull qwen2.5:14b
```
- 💪 Best analysis quality
- 💾 Large (~40 GB)
- 🖥️ Requires good GPU

#### ✅ Verify Model is Installed

```bash
ollama list
```

You should see your model in the list.

#### 🧪 Test the Model

```bash
ollama run llama3.1:8b "Say hello in one word"
```

### Step 6: Configure the Tool

Copy the example config and edit it:

```bash
cp config.example.yaml config.yaml
nano config.yaml    # or use any editor
```

**Minimum required changes:**

```yaml
# 👇 Set your model name (from `ollama list`)
ollama:
  model: llama3.1:8b                    # Change to your model
  host: "http://localhost:11434"        # Use local Ollama
  enabled: true
```

If your Ollama is running on a **remote server**, change the host:

```yaml
ollama:
  model: llama3.1:8b
  host: "http://YOUR_SERVER_IP:11434"   # Your remote Ollama
```

If you **don't want to use Redis** (simpler setup):

```yaml
session:
  enabled: false                        # Skip Redis entirely
```

## 🚀 Usage

### Basic Scan (Public Target)

```bash
python ashritha.py recon https://example.com
```

### Authenticated Scan

```bash
python ashritha.py recon https://example.com -u admin -p password123
```

### Quick Scan (Uses Defaults)

```bash
python ashritha.py quick https://example.com -u admin -p password123
```

### Scan Without Exploitation (Recon Only)

```bash
python ashritha.py recon https://example.com -u admin -p password123 --no-exploit
```

### Verbose Mode (For Debugging)

```bash
python ashritha.py recon https://example.com -u admin -p password123 --verbose
```

### Force Fresh Login (Ignore Cached Session)

```bash
python ashritha.py recon https://example.com -u admin -p password123 --force
```

### Generate Report

```bash
# Latest report
python ashritha.py report

# JSON format
python ashritha.py report --format json

# Specific target
python ashritha.py report example_com
```

### All Available Options

| Command | Description |
|---------|-------------|
| `recon` | Full reconnaissance with AI analysis and exploitation |
| `quick` | Quick scan with default settings |
| `report` | Generate report from previous scans |

| Option | Description |
|--------|-------------|
| `-u, --username` | Username for authentication |
| `-p, --password` | Password for authentication |
| `-r, --role` | Role for session (default: `default`) |
| `-f, --force` | Force fresh login |
| `--config` | Path to config file (default: `config.yaml`) |
| `--verbose` | Enable verbose logging |
| `--no-exploit` | Skip automated exploitation |

## ⚙️ Configuration

### Example `config.yaml`

```yaml
# Ollama AI Configuration
ollama:
  model: llama3.1:8b                    # Your Ollama model
  host: "http://localhost:11434"        # Ollama server URL
  enabled: true
  timeout_seconds: 60
  max_tokens: 2000
  temperature: 0.3

# Session Management (Optional)
session:
  enabled: false                        # Set to true if Redis is installed
  ttl_seconds: 3600
  refresh_threshold: 300
  redis_host: localhost
  redis_port: 6379
  redis_db: 0

# Web Crawler
recon:
  max_depth: 5
  max_pages: 1000
  timeout_seconds: 30
  concurrent_requests: 10
  user_agent: "Ashritha-VAPT-Bot/2.0"
  ignore_extensions:
    - .jpg
    - .jpeg
    - .png
    - .gif
    - .mp4
    - .mp3
    - .pdf
    - .doc
    - .docx
    - .ico
    - .svg
  priority_endpoints:
    - /api/
    - /rest/
    - /graphql
    - /admin
    - /dashboard
    - /swagger
    - /docs

# Automated Exploitation
exploitation:
  enabled: true
  max_payloads_per_vuln: 20
  timeout_seconds: 15
  safe_mode: true
  detect_errors: true

# Technology Fingerprinting
tech_fingerprint:
  enabled: true
  run_wappalyzer: true
  run_whatweb: true
  wappalyzer_timeout: 60
  whatweb_timeout: 60
  whatweb_aggression: 3

# CVE Matching
cve_matching:
  enabled: true
  use_nvd: false
  max_cves_per_tech: 10
```

## 🔧 Troubleshooting

### Ollama Connection Failed

**Error:** `Failed to connect to Ollama at http://localhost:11434`

**Fix:**
```bash
# Make sure Ollama is running
ollama serve

# In another terminal, test it
curl http://localhost:11434/api/tags
```

### Model Not Found

**Error:** `model 'xxx' not found (status code: 404)`

**Fix:**
```bash
# List installed models
ollama list

# Pull the model you want
ollama pull llama3.1:8b

# Update config.yaml with the exact model name
```

### Redis Connection Warning

**Warning:** `Redis connection failed: Connection refused`

**Fix (Option 1):** Install Redis
```bash
sudo apt install redis-server
sudo systemctl start redis
```

**Fix (Option 2):** Disable Redis in `config.yaml`
```yaml
session:
  enabled: false
```

### Wappalyzer / WhatWeb Not Found

**Warning:** `Wappalyzer not installed` / `WhatWeb not installed`

**Fix:** Install them, or ignore — the tool works without them.

```bash
# Wappalyzer
pipx install wappalyzer

# WhatWeb
sudo apt install whatweb
```

### Playwright Install Failed

**Error:** `playwright install chromium` fails

**Fix on Linux:**
```bash
playwright install-deps chromium
playwright install chromium
```

### Scan Too Slow

**Fix:** Reduce scan scope in `config.yaml`:
```yaml
recon:
  max_depth: 2               # Lower depth
  max_pages: 100              # Fewer pages
  concurrent_requests: 20     # More concurrency
```

### Getting Rate Limited

**Fix:** Lower concurrency:
```yaml
recon:
  concurrent_requests: 3      # Be gentle
  timeout_seconds: 60         # Longer timeout
```

## ❓ FAQ

### ❓ Do I need a GPU?

**No.** Ollama works on CPU. GPU makes it faster, but 3B–8B models run fine on CPU with 8–16 GB RAM.

### ❓ Do I need internet during scans?

**No** (after install). Ollama runs locally. Only the target needs internet (which it does by definition).

### ❓ Is my data sent anywhere?

**No.** Everything runs locally on your machine. The only external requests are to your target URL.

### ❓ Can I use a remote Ollama server?

**Yes.** Set `host` in `config.yaml`:
```yaml
ollama:
  host: "http://YOUR_SERVER_IP:11434"
```

> ⚠️ **Security:** Do NOT expose Ollama to the public internet without authentication. Use a VPN (Tailscale, WireGuard) or reverse proxy with auth.

### ❓ What if I don't have Ollama installed?

The tool will skip AI analysis and use rule-based analysis only. You'll still get basic vulnerability detection, but not AI-generated custom payloads.

### ❓ Can I run multiple scans at once?

**Yes**, if Redis is enabled. Otherwise, run one at a time or use separate terminals with different output folders.

### ❓ Where are results saved?

```
output/<target_domain>/
```

Each target gets its own folder, so scans never mix.

### ❓ How do I remove a scanned target?

```bash
rm -rf output/example_com
```

### ❓ Can I contribute?

Absolutely! Fork the repo, create a branch, and submit a pull request.
